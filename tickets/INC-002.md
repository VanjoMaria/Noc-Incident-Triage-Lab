# INC-002: ACL Wildcard Mask Error Allowing Blocked Traffic

| Field | Detail |
|---|---|
| **Ticket #** | INC-002 |
| **Severity** | Sev2 — security/compliance exposure. Sales (12.4.2.0/26) and Finance (12.4.2.128/26) VLANs able to communicate despite a segmentation policy requiring isolation. No outage, but a policy violation. |
| **Time Detected** | 10:00 am |
| **Symptoms Reported** | Finance team observed receiving files from the Sales team — communication between the two departments should have been blocked per company policy. |
| **Diagnostic Steps Taken** | 1. Ran ping tests Sales → Finance and Finance → Sales — both unexpectedly succeeded (should have been blocked).<br>2. `show access-lists block-sales-finance` on the multilayer switch — match counters showed hits landing on the `permit ip any any` line instead of the two `deny` lines, indicating the deny rules were not matching the traffic as intended.<br>3. Reviewed the wildcard mask on the deny lines — found `0.0.0.64` instead of the correct `0.0.0.63` for a /26 subnet. |
| **Root Cause** | The wildcard mask `0.0.0.64` only wildcards a single bit (matching 2 addresses), instead of the full 64-address range a /26 subnet requires (`0.0.0.63`). As a result, nearly all Sales↔Finance traffic (12.4.2.0/26 ↔ 12.4.2.128/26) fell through the deny lines and matched `permit ip any any` instead. |
| **Resolution** | Rebuilt the ACL with the corrected wildcard mask (`0.0.0.63`) on both deny lines. Verified via ping: Sales→Finance and Finance→Sales now fail with `Destination host unreachable` as expected; IT→Sales and IT→Finance still succeed. Confirmed via `show access-lists block-sales-finance`: deny line 10 shows 8 matches, deny line 20 shows 4 matches, and the permit line shows only 3 matches (unrelated legitimate traffic) — confirming the ACL now correctly enforces segmentation. |
| **Time to Resolve** | 15 minutes |
| **Prevention / Recommendation** | Use the standard wildcard calculation (255 − subnet mask octet) when writing ACLs for any non-/24 subnet, since non-default masks are where manual wildcard math is most error-prone. Add a post-deployment step to verify ACL match counters after initial testing, rather than assuming a config is correct once it's applied. |
